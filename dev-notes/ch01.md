## 阶段 5：T5 完成（结构化抽取，含一次返工）

**用户关键原话**
> 把用户的售后描述提取成订单号、诉求类型、期望方案这样的固定字段，用 with_structured_output 实现。

**关键产出**
- `POST /extract`，Pydantic 模型 `AfterSaleInfo`（`order_no` / `request_type` / `expected_solution`），调用 `with_structured_output(..., method="function_calling")`。
- 实测：带订单号描述返回 `{"order_no":"20241114001","request_type":"换货","expected_solution":"希望尽快更换一副新的蓝牙耳机"}`；无订单号描述返回 `"order_no": null`，类型判为「物流异常」；空请求体返回 422。

**拒绝与纠偏**
- 没有为了绕开报错而改用 `deepseek-chat` 或其他模型：先定位根因再修。

**翻车与返工**
- 首次调用 `/extract` 返回 500：`400 Thinking mode does not support this tool_choice`。
- 用 Context7 查 DeepSeek 官方文档确认：思考模式不支持 `required` / 指定 tool，需先关闭思考模式（`thinking.type=disabled` 或 `reasoning_effort=none`）。
- 返工方案：新增 `structured_llm`，仅在结构化抽取时通过 `extra_body={"thinking": {"type": "disabled"}}` 关闭思考；由 `.env` 的 `DISABLE_THINKING` 控制，避免影响其他上游。重测通过。
